# Синхронизация с апстримом (DrKLO/Telegram)

Наши правки живут не в форке апстрима, а как **список правок** `scripts/polysrv_edits.json`
(133 замены в 76 файлах + 8 новых файлов + keystore). Поэтому апстрим можно обновлять
без ручного переноса: скрипт заново накладывает правки на новую версию.

## Локально

```bash
# 1) взять свежий апстрим
git clone --depth 1 https://github.com/DrKLO/Telegram.git /tmp/tg && cd /tmp/tg

# 2) наложить наши правки
python3 /путь/к/нам/scripts/patch_polysrv.py --target /tmp/tg

# проверить заранее, лягут ли правки:
python3 scripts/patch_polysrv.py --target /tmp/tg --check --strict
```

Флаги:
| флаг | что делает |
|---|---|
| `--check` | только проверить (файлы не меняются) |
| `--strict` | ненайденные куски — ошибка (иначе просто отчёт) |
| `--reverse` | откатить правки |
| `--native-only` / `--java-only` | только `jni/` или только Java |
| `--submodules` | инициализировать сабмодули |
| `--api-id N --api-hash H` | подставить свой api_id/api_hash (my.telegram.org) |
| `--keystore PATH` | подставить свой release.keystore |

Скрипт не падает, если кусок не нашёлся: он применяет остальное и печатает отчёт
(что именно не нашлось) — обычно это значит, что апстрим изменил те же строки,
и правку надо поправить руками.

## Автоматически (GitHub Actions)

В репо есть воркфлоу `.github/workflows/sync-upstream.yml`:

* каждые 6 часов + вручную (Actions → Sync upstream → Run workflow);
* тянет `DrKLO/Telegram`, накладывает наши правки, проверяет, что ключевые куски на месте;
* кладёт результат в ветку `upstream-sync` и открывает PR;
* по желанию собирает APK (arm64) и отдаёт его артефактом;
* если наши правки больше не ложатся на апстрим — воркфлоу падает с отчётом,
  результат **не** коммитится (ничего не ломается молча).

## Пересборка `polysrv_edits.json`

После правок в нашем коде список надо перегенерировать:

```bash
python3 scripts/generate_polysrv_edits.py [base_commit]
# base_commit по умолчанию — upstream 13.0.3 (7183)
```

Вручную обычно не нужно: воркфлоу `.github/workflows/update-polysrv-edits.yml`
пересобирает файл на каждый push в `master` и сам коммитит результат
(коммит `Обновлён polysrv_edits.json`). Коммит бота не запускает воркфлоу снова,
поэтому цикла нет. Если файл не изменился — коммита не будет.
